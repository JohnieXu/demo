## 归档规范

- 一坑一档：一次排查一个文件，文件名用 kebab-case 描述问题本身。
- 头部必须有元信息块：`owner` / `updated` / `related`。
- 结构建议：结论 → 现象与报错特征 → 触发条件 → 根因 → 排查决策路径 → 修复方案 → 验证方式 → 遗留风险 → TODO。
- 「排查决策路径」必须记录**被否决的方案及否决理由**，避免后人重复走弯路。
- 未闭环的核查项写进 TODO 并标 `- [ ]`，完成后回写结论并更新 `updated`。
