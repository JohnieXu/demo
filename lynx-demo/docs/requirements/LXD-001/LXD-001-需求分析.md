# LXD-001 需求分析：flightResource 迁移至 lynx-demo

> 负责人角色产物。本阶段仅需求侧分析，未阅读/浏览任何代码实现（事实来源：PRD、源端目录清单枚举、用户确认决策）。
> 状态：✅ 完成（子方案责任人已逐项确认，盘问门禁通过）

## 1. 需求概述与业务目标

将 `h5-journey-monorepo/packages/legacy-app/src/flightResource`（Vue 3.5 + Vant + axios + Pinia，14 页面域、7 service 模块、11 utils、2 Pinia store，111 个文件）的机票业务能力迁移至 `johniexu-demo/lynx-demo`（ReactLynx），本期闭环"查询→列表→舱位→填单→订单"核心链路。

业务目标：
1. 形成一条 Lynx 上可实机走通的完整机票链路 demo
2. 沉淀一套可复用的迁移范式：service→DDD 仓储、utils→纯函数、Pinia→zustand、Vue 视图→ReactLynx 重写
3. 让既有未闭环的 travel-domain/travel-data flight 数据层获得消费方

## 3. 业务模块与链路梳理

### 3.1 页面域清单（14 个，按本期归属标注）

| 页面域 | 业务职责 | 本期归属 |
| --- | --- | --- |
| query | 出发/到达城市、日期查询入口 | Must（REQ-001） |
| citySelect | 城市选择（可独立页或内嵌） | Should（REQ-009） |
| flightList | 航班列表、筛选排序、价格标签 | Must（REQ-002） |
| cabinList | 舱位等级 Tab、产品组选择 | Must（REQ-003） |
| orderFill | 填单：乘机人、联系人 | Must（REQ-004） |
| passenger | 乘机人管理 | Should（REQ-010） |
| orderDetail | 订单详情 | Must（REQ-005） |
| orderList | 订单列表 | Must（REQ-005） |
| flightPay | 支付 | 非本期 |
| refundApply | 退票申请 | 非本期 |
| beneficiaryManage | 受益人管理 | 非本期 |
| myPage | 我的 | 非本期 |

### 3.2 链路流转

```
Query（城市+日期） → FlightList（筛选/排序） → CabinList（舱位/产品组）
  → OrderFill（乘机人/联系人） → 提交 → OrderDetail → OrderList
```

跨页面交互：城市数据经 store 共享（city/routeCity）；填单页依赖列表页携带的舱位/产品组上下文；订单详情/列表经订单号衔接。异常分支：列表查询超时（超时占位图）、无航班（空态占位图）、填单校验失败（validation service）。

### 3.3 支撑模块（非页面）

- 7 个 service 模块（axios 封装）：flight、citySelect、orderDetail、passenger、beneficiaryManage、validation、index
- 11 个业务 utils（纯逻辑）：cabinGradeTabs、cabinProductGroups、enterpriseTmcPrice、flightApiVersion、flightHighlightAirport、flightPriceTag、orderSource、beneficiaryExclusiveRelation、beneficiaryFlightSession、beneficiaryPassengerPendingTip、beneficiaryPassengerSelectable（后 4 个属受益人域，随 beneficiaryManage 非本期；**待澄清项 R-01**：本期是否仍迁移这 4 个 utils 中被核心链路引用的部分）
- 2 个 Pinia store：city、routeCity
- 2 个 composables（useListQueryTimeout、usePageActive）+ 1 个 hook（useIframeDocumentWrite，iframe 方案 Lynx 不适用，**待澄清 R-02**）
